# Field Notes (deploy-test-astro)

A small, static **knowledge/library site** built with [Astro](https://astro.build).
It demonstrates an Astro content collection, multiple article/detail pages, nested
category routes, local assets and a real, dependency-free **client-side search** with
an empty-search state. There is no database and no backend — the production output in
`dist/` is fully static.

## What you get

| Feature | Where |
|---|---|
| Content collection (`src/content/articles/`, typed schema) | `src/content.config.ts` |
| Article detail pages (9 notes, markdown) | `/library/articles/[slug]/` |
| Category pages (Guides / Recipes / Reference) | `/library/categories/[name]/` |
| Client-side search + filters + empty state | `/library/` (embedded, instant) |
| Nested routes and 404 | `/library/categories/`, `/404` |
| Local assets (logo/hero, hashed at build) | `src/assets/`, `public/` |
| Build/release marker in every footer | generated by `scripts/build-info.mjs` |
| Automated unit + smoke verification | `npm test` |

## Requirements

- Node.js **22.12 or newer** (pinned in `engines`)
- npm (a committed `package-lock.json` makes installs reproducible)

## Install, build, run

```bash
npm ci                 # reproducible install from the lockfile
npm run dev            # dev server on http://127.0.0.1:4321
npm run build          # emit the static site into dist/
npm run preview        # serve the built dist/ on http://127.0.0.1:4321
npm run check          # astro check (type checks)
npm test               # unit tests + end-to-end smoke suite
```

Production values for a static host:

| Setting | Value |
|---|---|
| Build command | `npm run build` |
| Output directory | `dist` |
| Runtime | Static (no server, no database) |
| Preview server | `npm run preview` (127.0.0.1, port 4321 / `--port` / `PORT`) |

## Environment configuration

There are **no secrets** in this site. Copy `.env.example` if you want to set the optional
`PORT`/`HOST` values used by the dev/preview servers.

## Health and persistence

This is a **static site**: there is no database, backend or background worker, so traditional
liveness/readiness probes and restart/redeploy persistence checks do not apply. `/healthz.txt`
is an explicit static availability marker only — real deployment status is tracked in
[VERIFICATION.md](./VERIFICATION.md), never inferred from a static file.

## Verification

- `scripts/build-info.mjs` writes build metadata (commit, astro version, build time) to a
  gitignored `src/generated/` file; every page footer shows the exact revision.
- `tests/unit/search.test.mjs` tests the pure search matcher (`src/lib/search.mjs`).
- `scripts/smoke.mjs` builds the site, serves the built `dist/`, runs HTTP checks on every
  nested route, verifies asset hashing and the 404 page, and drives real browser checks of the
  search (using a system Chromium when present).

## Limitations

- Site content is static markdown; adding/removing articles requires re-deploying.
- Search runs entirely client-side over an embedded index — fine at this scale, not a
  replacement for a full-text engine on thousands of documents.
- This repository is a public demonstration site; no sensitive data belongs in it.
